# 仮想テストレポート — UXバッチ実装（2026-06-28）

## テスト対象

- よく買うものダイアログの「履歴から登録」ボタンを削除（機能休止）
- よく買うものダイアログに検索窓を追加（検索中はドラッグ並び替え非表示）
- メインリスト商品の長押しでBottomSheetメニューを表示（別タブ移動 / よく買うものに登録）
- 商品追加ダイアログに「よく買うものにも登録する」チェックボックスを追加（新規追加モードのみ）
- 商品名候補の源泉を履歴DBから現在のリスト内商品名に変更（`candidateNames`）

## テスター別評価

### 01 田中 美咲（34歳・専業主婦）

**シナリオ**：週次まとめ買いの前に「よく買うもの」を開き、今週の食材を一括でリストに追加する。野菜コーナー・肉コーナーで商品ごとにチェックしながら消化する。

**評価**：
- よく買うもの検索：20〜30品が登録されているため「肉」「野菜」で絞り込める検索窓は非常に便利。全選択との組み合わせで特定カテゴリの商品だけをリストに追加できる点を好む。
- 長押しメニュー：今週初めて買う食材をリストに追加後、「来週も買うからお気に入りに入れたい」という場面で長押しが使える。好評。
- チェックボックス：新規追加しながら同時にお気に入り登録できる点を「2度手間が省ける」と評価。
- 候補表示：現在のリスト内商品名が候補として出るため、同じ商品を数量違いで再追加するときに役立つ。ただし、以前は買ったことがあって今リストにない商品は候補に出なくなったため、一時的に不便を感じる。

**発見した問題・改善案**：長押し→「よく買うものに登録」で、すでに登録済みの商品でも重複して登録されてしまう。登録前に重複チェックをして警告するか、UPSERTに変更することが望ましい。

### 04 山本 拓也（41歳・フリーランスエンジニア）

**シナリオ**：家庭用と事務所用の2つのタブを使い分け。同期の安定性を意識しながら使う。コードを読む習慣があるため挙動の違和感に敏感。

**評価**：
- よく買うもの検索：`_filteredFavorites` ゲッターが `_favorites` から都度計算される設計は正しい。検索中に Dismissible でアイテムを削除した後 `_load()` が走って `_favorites` が更新され、`_filteredFavorites` も正しく再計算される点は堅固。
- 長押しメニュー：`showModalBottomSheet` の result を String で分岐する実装は明快。ただし `onMoveToTab` と `onAddToFavorites` どちらも null のときは `onLongPress` が null になり長押し自体が無効になる設計は的確。
- チェックボックス：`closeAfter: true` パスで `setState(() { _addToFavorites = false; })` が到達されないが、そのまま pop するため問題なし。コードの流れとして自然。
- 候補表示：`itemAsync.maybeWhen(data: ...)` でリアルタイムに候補が生成されるため、アイテム追加直後から候補に反映される。DBクエリなしで取得できる点はパフォーマンス上も好ましい。

**発見した問題・改善案**：`insertFavorite` に重複チェックがないため、長押しとチェックボックスの両方で同一商品が二重登録されるリスクがある。また、検索フィールドにクリアボタン（`suffixIcon: IconButton(icon: Icons.clear)`）があると検索解除がワンタップで済む。

## 優先度付き改善リスト

### 高

- **重複登録チェックの欠如（`insertFavorite`）**：長押しの「よく買うものに登録」・追加ダイアログのチェックボックスのどちらでも、すでに同名のよく買うものが存在する場合に重複して登録される。「既に登録されています」の警告またはUPSERT（同名なら上書き確認）への変更が必要。影響テスター：01・04・08。

### 中

- **長押し操作の発見性向上**：ITリテラシーが低めのユーザーには長押しメニューが存在することが伝わらない。ヘルプダイアログに「商品を長押しするとメニューが表示されます」の説明を追加することを推奨する。影響テスター：06・03。
- **BottomSheetにキャンセル操作の明示**：現在は外側タップ・スワイプダウンのみで閉じられる。「キャンセル」ListTileを最下部に追加するか、ハンドルバーで閉じられることを示すインジケーターを表示することで誤操作時の戸惑いを減らせる。影響テスター：02・06。
- **連続追加でのチェックボックス維持オプション**：複数品を連続してよく買うものにも登録したい場面で毎回チェックし直す手間が生じる。「連続追加中はチェックを維持する」オプションまたは挙動の見直しを検討する。影響テスター：10。

### 低

- **検索フィールドのクリアボタン**：検索中にワンタップでクリアできる `suffixIcon` を追加するとスムーズに全件表示へ戻れる。影響テスター：04・01。
- **チェックボックスラベルの短縮検討**：「よく買うものにも登録する」は小さい端末で折り返す可能性がある。「お気に入りにも登録」など短縮形を検討する。影響テスター：05。
- **候補表示の変更をヘルプに反映**：履歴からリスト内商品名への変更によりユーザーが「補完が出なくなった」と感じる場面がある。ヘルプの候補表示説明を更新することで混乱を防げる。影響テスター：01・03・07・10。

## 総評

よく買うもの検索窓の追加は登録品が多いユーザーから特に高い評価が得られており、全選択との組み合わせでの運用が自然に定着すると見込まれる。長押しメニューはITリテラシーが高めのユーザー層には直感的に発見・活用されているが、シニアユーザーや初心者には発見性の課題があり、ヘルプへの記載が対策として必要である。追加ダイアログへのチェックボックスは価格・個数を入力しながら同時にお気に入り登録できる点で連続登録ユーザーに好評だが、連続追加でのリセット挙動には改善の余地がある。候補表示のリスト内スコープへの変更は過去の履歴に依存していたユーザーにとって最初は違和感があるが、現在の文脈に即した候補が出るという点でUXの一貫性が向上している。全体として「操作の手数を減らす」方向の今回の改善バッチは好意的に受け入れられると評価するが、重複登録の防止は最優先で対処されることを推奨する。
