# 調査レポート：バックアップ画面「戻るボタン」要望対応（2026-07-29）

## 1. 概要

2026-07-29、クローズドテスターから「バックアップ読み込み画面とバックアップの端末保存画面に戻るボタンがあった方がいい」というフィードバックを受けた。添付されたスクリーンショット2枚はいずれもAndroidの「ダウンロード」フォルダを表示するファイル一覧画面であり、上部バーにはハンバーガーメニュー・検索アイコン・オーバーフローメニュー（またはファイル保存操作時は新規フォルダアイコン・保存ボタン）のみが存在し、戻る矢印（バックアイコン）が見当たらない構成だった。

本レポートは、この指摘を受けて実施したコード調査の内容と、その結果導かれた結論・対応方針をまとめたものである。

## 2. 指摘内容（フィードバック原文）

> バックアップ読み込み画面とバックアップの端末保存画面に戻るボタンがあった方がいい

添付スクリーンショットの内容：Androidの「ダウンロード」フォルダを表示するファイル一覧画面。上部バーの構成要素はハンバーガーメニュー・検索アイコン・オーバーフローメニュー（ファイル保存操作時は新規フォルダアイコン・保存ボタン）のみで、戻る矢印（バックアイコン）は確認できなかった。

## 3. 調査内容

調査対象として `lib/screens/shopping_list_screen.dart` と `lib/services/backup_service.dart` を確認した。

### 3.1 バックアップの端末保存（`_exportBackup`）

- `_exportBackup()`（`lib/screens/shopping_list_screen.dart` 203行目付近）は、まずアプリ独自の `AlertDialog`（タイトル「バックアップ」、「キャンセル」「共有」「端末に保存」の3ボタン、207行目付近）を表示する。
- 「端末に保存」を選択すると `BackupService.saveToDevice()` が呼び出される。
- `BackupService.saveToDevice()`（`lib/services/backup_service.dart` 89〜100行目）の内部では `FilePicker.platform.saveFile(...)`（92行目）を呼び出している。これはAndroidのStorage Access Framework（SAF）を利用し、OS標準のファイル保存画面を起動する処理である。

### 3.2 バックアップデータの読み込み（`_importBackup`）

- `_importBackup()`（`lib/screens/shopping_list_screen.dart` 248行目付近）も同様に、まずアプリ独自の `AlertDialog`（タイトル「バックアップデータを読み込む」、「キャンセル」「読み込む」の2ボタン、252行目付近）を表示する。
- 「読み込む」を選択すると `BackupService.import()` が呼び出される。
- `BackupService.import()`（`lib/services/backup_service.dart` 149〜163行目）の内部では `FilePicker.platform.pickFiles(...)`（152行目）を呼び出している。こちらも同様にOS標準のファイル選択画面を起動する処理である。

### 3.3 判明した事実

スクリーンショットに写っていた「戻るボタンがない」画面は、いずれもアプリのFlutterコードが描画しているUIではなく、`file_picker` パッケージ経由で起動されるAndroid OS側のネイティブ画面（SAFピッカー）であることが確認できた。

なお、OS画面が開く前段のアプリ独自の確認ダイアログについては、`_exportBackup()`・`_importBackup()`のいずれにも既に「キャンセル」ボタンが実装済みであることを確認した。

## 4. 結論

指摘のあった「戻るボタンがない」画面はアプリのコードが描画するUIではなく、Android OSが提供するSAFピッカー（ファイル選択・保存画面）である。アプリのコードを変更してもこの画面のUI（戻るボタンの有無等）を制御することはできないため、アプリ側での対応は技術的に不可能である。
