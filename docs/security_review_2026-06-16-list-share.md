# セキュリティレビュー：リスト共有・バックアップ端末保存

**実施日**: 2026-06-16
**対象ブランチ**: `feat/list-share-backup-device`
**レビュー範囲**: 今回追加・変更した経路のみ（`BackupService.saveToDevice` / `shareList` / `import` 緩和、`shopping_list_screen.dart` のバックアップ保存先・リスト共有・読み込み文言）

---

## 1. チェック観点と結果

| 観点 | 結果 | 詳細 |
|------|------|------|
| 他フォルダへの不正アクセス | ✅ 問題なし | `saveToDevice` は `file_picker` の `saveFile`（Android は SAF）でユーザーが選んだ場所にのみ書き込む。`shareList` は `getTemporaryDirectory()`（アプリサンドボックス）に一時生成し `finally` で削除。ハードコードされた外部パスや任意パス書き込みなし |
| 共有ファイルの情報露出 | ✅ 問題なし | `shareList` は対象1リストの**未購入アイテムのみ**＋`favorites` 空で出力。他リスト・購入済み・履歴・購入状態（is_ad_free 等）は含まれない。ユーザーが明示的に選んだリストの内容のみ |
| 不正ファイルの取り込み（FileType.any 緩和後） | ✅ 問題なし | 拡張子フィルタは外したが、`parseAndValidate` で `version` 型・値、必須キー（lists/items/favorites）の型を検証。不正な場合は `FormatException` を投げ、UI は「読み込めないファイルです」等の汎用文言を表示。`importData` 側も `(num).toInt()` で型安全にキャストし、10件上限チェックを保持 |
| catch 節の内部情報露出 | ✅ 問題なし | `_exportBackup` の catch は固定文言「保存に失敗しました」。`e.toString()` やパスを露出しない。読み込み系も既存の switch/汎用文言を踏襲 |
| 一時ファイルの後始末 | ✅ 問題なし | `export` / `shareList` とも `finally` で一時ファイルを削除。`saveToDevice` は SAF へ直接 bytes 書き込みのため一時ファイルを作らない |
| 業務ルールの迂回（インポート経路） | ✅ 問題なし | リスト共有・端末保存ファイルも既存 `importData` を通り、10件上限・同名連番付与・favorites 重複スキップが共通適用される（Rules 準拠） |

---

## 2. 許容したリスク（記録）

- **FileType.any による任意ファイル選択**：ユーザーが極端に大きいファイルや非 JSON を選んだ場合、`readAsString` でメモリに読み込む。ただしユーザー自身の選択操作であり、ローカル単一ユーザーアプリのため悪用余地は小さい。中身は `parseAndValidate` で弾かれる。個人アプリ規模では許容範囲。
- **共有ファイルは平文 JSON**：リスト内容（商品名・価格・個数）が平文で共有される。これは「他者と共有する」機能の性質上、意図された動作。機微情報（購入状態・課金フラグ・全データ）は含めない設計で最小化済み。

---

## 3. 結論

今回の変更で新規の脆弱性は検出されなかった。共有・保存・読み込みのいずれの経路もアプリサンドボックス／SAF の範囲内で完結し、外部情報の露出や業務ルールの迂回は発生しない。リリース可。
