## 2. 許容したリスク（記録）

**同意ダイアログ表示中の背後処理**：同意ダイアログの表示中も、背後でホーム画面の初期化・AdMob 初期化・広告読込が進みます。マスター承認済みの仕様判断ですが、同意前に広告リクエストが走り得る点を記録します。

**「同意しない」の挙動**：`SystemNavigator.pop()` で Activity を終了するのみで、プロセスは直ちには消えません（エミュレーターで pid の残存を確認）。同意は保存されないため、再起動時はダイアログが再表示されます。

**同意の保存先**：端末内の SharedPreferences のみで、サーバー側に同意記録は残りません。改ざんや端末データ消去で同意状態は変わり得ますが、本アプリはアカウントを持たないため許容します。

## 参考（確信度低・優先度低）

**リンク起動失敗時の SnackBar の見えにくさ**：失敗時の SnackBar は背後の Scaffold に対して表示されるため、モーダルの下に出て見えにくい可能性があります（失敗経路は実機未確認）。セキュリティ上の問題ではなく UX の観点です。

**巨大な有限値の `toInt()` 挙動**：`normalizeImportedPrice` に桁あふれするほど巨大な有限値（例：1e300）を渡した場合の `toInt()` の挙動は、今回の確認では検証していません。
