## 検査結果（クリーン確認済み）

**SQLインジェクション：なし**　全クエリが `where: 'id = ?', whereArgs: [...]` のプレースホルダー経由で実装されており、ユーザー入力の直接埋め込みはありません。

**ファイルシステム不正アクセス：なし**　DBパスは `getDatabasesPath()` によりアプリサンドボックス内に限定されています。他フォルダへのアクセスは一切ありません。

**ネットワーク通信：なし**　カスタムHTTP通信は存在せず、AdMob SDK・`in_app_purchase` SDK に完全委譲しています。証明書検証バイパスや `HttpClient` の直接操作もありません。

**ハードコードシークレット：なし**　AdMobユニットID（`ca-app-pub-...`）は半公開情報であり、パスワード・認証トークン類のハードコードは存在しません。

**挙動不明確な関数・変数：なし**　`insertItemWithId` の `ConflictAlgorithm.replace`、`normalizeAllSortOrders` の未使用化、楽観的更新など、意図が明確にコードで表現されています。

## 不採用理由（主要3件）

**IAPバイパス**はクライアントサイドの認可チェック欠如に分類され、サーバーサイドの責務です。また、ルート化端末での SharedPreferences 書き換えはデバイス層の問題であり、アプリ層の脆弱性に該当しません。

**QuantityFieldのバリデーション欠如**は経路として存在しますが（0や負数がDBに書かれる）、影響を受けるのはローカルのシングルユーザーのみであり、外部攻撃者がトリガーする手段がありません。セキュリティ脆弱性ではなくコード品質問題（`favorites_dialog.dart` との一貫性不足）として管理すべき事項です。

**エラー文字列のUI直表示**は端末所有者本人のみが参照でき、外部流出経路がないため、このアプリの脅威モデルでは対象外です。

## 総評

**セキュリティ懸念は確認されませんでした。** SQLインジェクション対策・ファイルシステム隔離・ネットワーク通信の外部SDK委譲はいずれも適切に実装されています。

なお、`QuantityField` のバリデーション欠如は `favorites_dialog.dart` との一貫性問題として、セキュリティとは別にコード品質改善の候補として記録しておくことを推奨します。
